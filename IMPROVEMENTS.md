## ✅ 2. Разъяснить смысл скобок в `input()`
- **Дата:** 2026-09-10
- **Проблема / вопрос:** «если написано `name = input()`, то я в скобки могу ставить значения по правилам питона?» Пользователь думает, что `input("Анна")` вставляет значение `Анна` (мы это уже видели в задаче 1: `input("Анна")`).
- **Факты (для справки/шпаргалки):**
  - Текст в скобках `input("...")` — это **подсказка-приглашение** (prompt): она просто выводится на экран перед ожиданием ввода, а не становится значением переменной.
  - Задать своё значение можно так: `name = "Андрей"` — это **не ошибка Python**, код честно выполнится. Но в тренажёре задание не пройдёт проверку: чекер подставляет СВОЙ тестовый ввод и сравнивает вывод с ожидаемым. Захардкоженное имя этот тест провалит — хотя сам код рабочий.
- **Что сделать:** добавить в материалы/шпаргалку мини-блок: «input('текст') — это подсказка, а не значение. Хочешь значение сам — пиши name = 'Анна'. В тренажёре так задача не зачтётся, но Python ругаться не будет».
- **Дополнение (2026-09-10):** второй слой заблуждения вскрылся позже — «input() просто костыль, чтобы было какое-то значение? правильней писать name = 'Андрей'? а инпуты для автоподстановки?». Важно донести: input() — это НАСТОЯЩИЙ механизм чтения данных пользователя, как в реальных программах; хардкод — это одноразовое решение.
- **Сделано (2026-09-10):** в `content/basics/01_variables.json` добавлен note-блок (после warning про тип input) с объяснением prompt vs значение, хардкода и проверки; ссылка на режим «Твой ввод».

## ✅ 3. Режим «потыкать самому» — ручной ввод
- **Дата:** 2026-09-10
- **Откуда:** «просто получается я имя не ввожу, а оно автоматом вставляется, а хочется самому потыкать».
- **Идея:** рядом с кнопкой «▶ Запустить на примере» добавить «🧪 Запустить со своим вводом»: поле (или мини-терминал), куда пользователь сам печатает строки stdin, и код выполняется с ними. Свободный запуск без проверки тестами.
- **Польза:** экспериментальное обучение, снимается ощущение «магии» при автоподстановке примера.
- **Сделано (2026-09-10):** поле ввода задачи переоформлено в полноценный блок «⌨️ Твой ввод» (`app/app.js`, `app/app.css`):
  - поле объявлено редактируемым по умолчанию, с подсказкой «каждый input() съедает одну строку сверху вниз»;
  - кнопка «▶ Запустить с моим вводом» (бывшая «на примере»);
  - кнопка «↺ ввод из примера» возвращает данные примера одним нажатием;
  - подсказка-подпись поясняет, что «Проверить» всегда гоняет тесты со своим вводом.
- **Примечание:** сделан вариант «печатаешь строки заранее, потом запуск». Живой терминал (когда программа спрашивает, а ты отвечаешь построчно) — отдельная идея, см. заметку 4.

## ✅ 9. «Плагин» автоформата отступов в редакторе задач
- **Дата:** 2026-09-11
- **Просьба:** «можно встроить в строку ввода плагин, который будет форматировать код как положено? ввожу код, а пишет, что отступы не сделаны, хотя код может быть верным; пусть авто подстраивает пробелы».
- **Факт для справки:** «пишет, что отступы не сделаны» — это не каприз тренажёра, а IndentationError самого Python: отступы — часть языка, без них код формально неверен. Но облегчить жизнь новичку — святое.
- **Сделано (2026-09-11):**
  - новый модуль `app/format.js` (window.PyFmt.autoIndent): эвристический выравниватель — табы → 4 пробела, глубина по «:», слова-сдвигатели else/elif/except/finally/case, не лезет в тройные строки и многострочные скобки; 12 тестов `tools/test_format.mjs`;
  - в карточке задачи над редактором панель «🪄 Автоотступы» + подсказка по клавишам;
  - умный ввод в редакторе: Enter повторяет отступ строки, после «:» — +4 пробела; Shift+Tab — сдвиг назад; Tab по выделенному блоку — сдвинуть все строки; Backspace по отступу съедает сразу 4 пробела;
  - `format.js` подключён к index.html, сборке (`build_site.py`: хэш + standalone) и «жёсткой перезагрузке»;
  - честно помечено: эвристика, не black — после «🪄» глазами пробежать вложенное.
- **На будущее:** если захочется настоящий black — только через Pyodide+micropip (тяжело и требует сети), держим как запасной вариант.
