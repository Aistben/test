# Python-тренажёр: Основы + Мостик

Веб-приложение для самообучения: список тем слева, теория и задачи с автопроверкой
справа. Python работает прямо в браузере (Pyodide), сервер и сборка не нужны.
Темы открываются по порядку: следующий урок становится доступен, когда решены
все задачи предыдущего. После последней сданной задачи открывается
**«Повторение»**: можно закрепить материал или кнопкой «К обучению»
перейти к следующей теме.

## Как запустить

Двойной клик по `index.html` — работает локально, интернет нужен только на первую
загрузку Python (~10 МБ с CDN, дальше кэш браузера). `index.html` не самодостаточен:
нужна папка `app/` рядом (её стили и скрипты он подключает).

Для «всё в одном» есть генерируемый `pypath.html` — вся программа в одном файле
(стили, ядро, данные уроков и логика инлайном): его можно скопировать на флешку
или телефон и открыть где угодно. Пересобирается вместе с `app/data.js`.

Альтернатива через локальный сервер (или для проверки со смартфона):

```bash
python3 -m http.server 8000
# открыть http://localhost:8000
```

## Как это устроено

- `content/` — уроки (чистый JSON, источник правды), `content/index.json` — реестр этапов.
- `engine/py/harness.py` — исполнение кода и сверка с тестами. Один и тот же файл
  используют браузерное приложение и валидатор — «прошло в валидаторе» == «пройдёт в тренажёре».
- `tools/build_site.py` — собирает уроки + harness в `app/data.js`, генерирует
  `pypath.html` и вписывает в `index.html` версии ассетов `?v=хэш` (браузерный кэш
  не может залипнуть на старых стилях/скриптах). Запускать после любой правки
  контента или `app/`.
- `tools/validate_lessons.py` — проверка уроков:
  `python3 tools/validate_lessons.py --strict`.
- `tools/test_core.mjs` — логика открытия тем: `node tools/test_core.mjs`.
- `tools/test_review.mjs` — адаптивная выборка, статистика и совместимость
  бэкапов: `node tools/test_review.mjs` (без браузера и сторонних зависимостей).
- `tools/test_review_browser.mjs` — сквозные проверки интерфейса с настоящим
  Pyodide, включая самостоятельный `pypath.html` (запуск ниже).
- `PYTHON_PLAN.txt` — план обучения, чеклисты и дневник (вкладка «Мой план» в приложении).
- `app/` — само приложение: `core.js` (правила открытия тем, чистые функции),
  `app.js` (интерфейс), `app.css`, генерируемый `data.js`.

## Прогресс

Решённые задачи, черновики кода и статистика повторения хранятся в localStorage браузера. localStorage
привязан к «источнику» (file://, localhost, превью — это разные хранилища), поэтому
в футере сайдбара есть экспорт/импорт прогресса в `pypath-progress.json` — так
прогресс переносится между `index.html` и `pypath.html` и между компьютерами.
Там же сброс прогресса и «жёсткая перезагрузка без кэша».
Отметки `[x]` в `PYTHON_PLAN.txt` — единственный официальный учёт прогресса
(правила — раздел 10 плана).

## Возможности карточки задачи

- «Проверить» — прогон по всем тестам задачи (как на экзамене).
- «▶ Запустить на примере» — честный запуск: код идёт со значением из поля
  «ввод программы» (автозаполняется input первого открытого теста), файлы
  visible-теста создаются в песочнице, а после работы показывается содержимое
  созданных программой файлов.
- После сдачи открывается кнопка «👀 эталонное решение» — сверь свой стиль.

## Повторение пройденного

Режим открывается после первой **полностью пройденной** темы и доступен в
сайдбаре по кнопке **«Повторение»**. После завершения каждой новой темы приложение
показывает обзор повторения; продолжение курса остаётся доступно сразу.
Для старого сохранённого прогресса ничего проходить заново не нужно.

- Сессия — **5 карточек** со случайными задачами из завершённых тем.
  Используется существующий банк заданий курса, а не генерация новых условий.
- **Все пройденные темы** — смешанная адаптивная практика. **Слабые места** —
  только темы с задачами повышенного приоритета; если таких нет, это явно
  показано. Состав тем в этом режиме фиксируется на одну сессию.
- Ошибочная проверка и «Не помню — повторить позже» повышают приоритет задачи.
  Учитывается и приоритет темы в целом. Самостоятельное решение с первой
  попытки снижает приоритет; старые ошибки не остаются вечным штрафом.
  Давно не встречавшиеся задачи получают дополнительный вес.
- Одна задача не идёт дважды подряд, если есть альтернативы. Предпоследняя
  получает меньший вес, но не исключается полностью: адаптация работает даже
  с тремя задачами первой темы. Выбор вероятностный, не жёсткое расписание.
- **«Вспомнить теорию»** открывает краткую памятку и полную теорию с запускаемыми
  примерами. Подсказки тоже доступны. Помощь не считается ошибкой, но итог
  не относится к решениям «с первой попытки, без помощи».
- Одно нажатие «Проверить» — одна попытка, независимо от числа тестов. Пустой
  редактор, загрузка Python, сбой движка и «Запустить на примере» не добавляют
  ошибок. Успешную карточку нельзя засчитать повторными нажатиями.
- Черновики повторения **отдельны от решений в уроках**. Решённая карточка
  при следующем появлении начинается с пустого редактора. Незавершённый
  черновик сохраняется; при повторном появлении задачи его можно продолжить.
- Ошибки и пропуски не отменяют зачёт урока и не запирают следующие темы.
  Сессию можно завершить досрочно — незавершённая карточка не считается ошибкой
  или пропуском. Итог показывает решённые задачи, помощь и пропуски.

Статистика собирается при первом прохождении задач курса и в повторении,
начиная с этого обновления. В старых данных истории ошибок нет — она не
восстанавливается и не выдумывается. Экспорт версии 2 включает статистику,
последние выданные задачи и черновики повторения; импорт версии 1 поддерживается.
Сброс прогресса по подтверждению сбрасывает также повторение.

### Проверки

```bash
node tools/test_core.mjs
node tools/test_review.mjs
python3 tools/validate_lessons.py --strict
python3 tools/build_site.py
```

Для сквозной проверки в Linux нужны только тестовые зависимости (не нужны
для работы приложения). Они устанавливаются в игнорируемую папку `tmp/`:

```bash
npm install --prefix tmp/qa --no-save --package-lock=false \
  playwright@1.63.0 pyodide@0.26.4 @sparticuz/chromium@149.0.0
# В другом терминале запусти сервер из корня: python3 -m http.server 8000
NODE_PATH="$PWD/tmp/qa/node_modules" node tools/test_review_browser.mjs
```

Тест использует изолированный профиль Chromium и не меняет прогресс пользователя.
Проверяет разблокировку, автоматический переход, ошибки/помощь/пропуски,
защиту от повторного зачёта, сохранение, оба формата импорта, экспорт, сброс,
мобильную вёрстку и оба HTML-входа. Все эталонные решения дополнительно
исполняются настоящим Pyodide: файлы версии 0.26.4 берутся из npm-дистрибутива
для воспроизводимости, результаты проверок **не подменяются**.
Можно задать `BASE_URL` и `CHROMIUM_EXECUTABLE` для другого сервера/браузера.

## Публикация: GitHub Pages

Канонический адрес проекта —
[`https://aistben.github.io/test/`](https://aistben.github.io/test/).

1. В настройках репозитория открой **Pages** и выбери **Deploy from a branch**:
   ветка `main`, папка `/ (root)`. Включи **Enforce HTTPS**.
2. В корне репозитория **не должно быть файла `CNAME`**, а поле **Custom domain**
   в настройках Pages должно быть пустым. Кастомные домены в проекте не
   используются: любой такой домен включает постоянный редирект с
   `aistben.github.io/test/` и ломает канонический адрес.
3. `.nojekyll` отключает обработку Jekyll — Pages публикует файлы как есть.

Если браузер всё ещё уводит на какой-то посторонний домен, это закэшированный
редирект `301`: обычное обновление страницы его не сбрасывает. Открой
канонический адрес в приватном окне либо очисти данные сайта.
