================================================================================
  1. ЧЕСТНО О СРОКАХ И ПОЧЕМУ PYTHON
================================================================================

Сроки (при 1–2 часах каждый день):
  - 1.5–2 месяца   — свободно пишешь скрипты, понимаешь логику.
  - 3–4 месяца     — умеешь один «сэндвич» (бэкенд ИЛИ автоматизация)
                     -> можно брать мелкие заказы.
  - 6–12 месяцев   — уровень для первой удалённой работы.

Не гонись за «деньгами за 2 недели» — гонись за УМЕНИЕМ за 2 недели.

Почему Python:
  - Простой язык для входа, логика видна сразу.
  - Огромный спрос: бэкенд, аналитика, автоматизация, боты, парсинг, ИИ.
  - Первые заказы на фрилансе реально брать уже на раннем этапе.
  - Удалённых вакансий больше, чем кажется.


================================================================================
  2. ГДЕ Я СЕЙЧАС: ЧЕКЛИСТ ЭТАПА 1 — ОСНОВЫ (1.5–2 месяца)
================================================================================

Правило отметки: [x] ставится только если могу написать это РУКАМИ, без
подглядывания в конспект и без ИИ. «Понял, когда прочитал» — это ещё не [x].

Темы:
  [ ] Переменные, типы данных (int, float, str, bool), преобразование типов
  [ ] Ввод/вывод: print(), input(), f-строки
  [ ] Условия: if / elif / else, логические операторы and / or / not
  [ ] Циклы: for, while, range(), break / continue
  [ ] Функции: def, параметры, return, значения по умолчанию, область видимости
  [ ] Списки: индексы, срезы, append / pop / sort / len, перебор, вложенные списки
  [ ] Словари: ключ -> значение, get(), items(), перебор, словарь списков
  [ ] Строки: split / join / strip / replace / upper / find, срезы, in
  [ ] Числа: // % ** round() abs() min() max() sum()
  [ ] Работа с файлами: open(), режимы r / w / a, with ... as, чтение построчно

Мини-задачи (каждая написана самостоятельно и доведена до рабочего состояния):
  [ ] Калькулятор (4 действия, защита от деления на ноль)
  [ ] Генератор паролей (длина и набор символов задаются)
  [ ] Переводчик температуры (C <-> F, в обе стороны)
  [ ] Игра «угадай число» (со счётчиком попыток и подсказками «больше/меньше»)

Экзамен «этап 1 закрыт» (30–40 минут, без подсказок):
  Написать программу, которая читает текстовый файл со строками вида
  «название;цена», считает общую сумму, находит самый дорогой товар и
  записывает результат в другой файл. Ввод с ошибками (пустая строка,
  цена не число) не должен ронять программу.
  [ ] Сдал сам себе -> этап 1 закрыт, переходим к разделу 3.

  [ ] Кортежи (tuple) и множества (set): чем отличаются от списка, когда что брать

  [ ] Модули и импорт: import, from ... import, свои модули, if __name__ == "__main__"

      чтобы читать чужой код и документацию библиотек)
  [ ] *args / **kwargs, lambda, sorted(key=...)
  [ ] Стиль кода PEP 8: осмысленные имена, отступы, комментарии, докстринги

3.3. Мышление программиста (не темы, а привычки)
  [ ] Читаю сообщение об ошибке САМ до того, как спросить ИИ
  [ ] Разбиваю задачу на шаги (на бумаге / в комментариях) ДО написания кода
  [ ] Умею найти нужное в docs.python.org и в документации библиотеки
  [ ] ИИ — ревьюер («найди ошибки», «объясни, почему так»), а не автор кода за меня

  8. КАК УЧИТЬСЯ, ЧТОБЫ НЕ СГОРЕТЬ
================================================================================

Делать:
  - Каждый день 1–2 часа, а не раз в неделю 6.
  - Правило 50/50: половина — теория, половина — пишешь сам.
  - Одна ветка одновременно. Выбрал — не отвлекайся.
  - Готово лучше, чем идеально. Довёл до конца — это успех.
  - Застрял на 3 дня — гугл / документация / чат. Не сидеть молча неделю.
  - После каждой темы — одна маленькая программа.

НЕ делать:
  - Не начинать Django / FastAPI до «Мостика» (раздел 3) — будет каша.
  - Не проходить 3 курса параллельно. Один курс + свои проекты.
  - Не учиться ТОЛЬКО в браузерном редакторе — ставь Python локально (3.1).
  - Не копировать код ИИ, не поняв каждую строку. ИИ объясняет и проверяет —
    пишу я.
  - Не бросать проект на 80%. Лучше маленький и законченный.
  - Не покупать платные курсы, пока не пройдены бесплатные из раздела 7.

Оценка прогресса — каждые 2 недели, три вопроса (ответы — в дневник):
  1. Что я вчера написал руками?
  2. Могу объяснить, как работает моя программа?
  3. Где застрял и как решил?

Если через 3–4 недели ветки понял, что «не моё» — ок, менять ветку внутри
Python можно. Но после месяца реальной практики, а не после 3 дней.

    заголовки разделов — как сейчас (линии из «=»). Разделы не перенумеровывать:
    на номера есть ссылки внутри файла.

10.3. Как сохранять в git (после КАЖДОГО занятия)
  git status                                # что изменилось
  git add .                                 # добавить всё (кроме .gitignore)
  git commit -m "todo: сохранение в json"   # одна строка: ЧТО сделано
  git push                                  # отправить на GitHub

  Сообщение коммита — по-русски или по-английски, но конкретно:
    плохо:   "fix", "update", "изменения"
    хорошо:  "expenses: считаю сумму за месяц", "plan: закрыл этап 1"
  Если git ругается на конфликт или «rejected» — не дёргать команды наугад,
  скопировать сообщение целиком и спросить (ИИ / чат), приложив вывод git status.

10.4. Что НИКОГДА не коммитить
  - venv/ и .venv/           — виртуальное окружение (ставится заново за минуту)
  - __pycache__/, *.pyc      — мусор интерпретатора
  - .env                     — токены ботов, пароли, ключи API.
                               Токен Telegram-бота в публичном git = бот угнан.
                               Если случайно закоммитил — сразу перевыпустить токен.
  - большие файлы данных (> 5 МБ), выгрузки, скачанные картинки
  Всё это уже прописано в .gitignore. При добавлении нового типа мусора —
  дописывать туда же.

10.5. Правила для ИИ-помощника (скопировать в начало разговора)
  ------------------------------------------------------------------------
  Прочитай файл PYTHON_PLAN.txt в репозитории. Я учу Python по этому плану.
  Мой текущий этап указан в шапке файла и в разделах 2–3.
  Правила:
  1. Не предлагай темы и библиотеки из следующих этапов, пока не закрыт текущий.
  2. Не пиши код за меня. Давай подсказку, псевдокод или наводящий вопрос.

  5. Если правишь PYTHON_PLAN.txt — соблюдай раздел 10.2: не удаляй историю,
